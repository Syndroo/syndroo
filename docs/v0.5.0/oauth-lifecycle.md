# OAuth lifecycle implementation boundary

Root architecture decision. Complements public-api.md, credential-resolution.md and security-decisions.md; no acceptance claim.

## Scope and ownership

Implement three bounded scopes in order: (1) portable driver contract plus connect/callback/operation reads, (2) portable complete/refresh, (3) concrete Worker OAuth driver. SDK work may proceed independently. No edits to frozen credential-store contracts, accepted platform strategy modules or exhausted transport/crypto/D1 scopes are required. Root coordinates one additive application-export update before concrete driver/runtime wiring; portable tests can use relative source imports meanwhile. Runtime wiring follows separately.

The portable application owns state transitions, encryption context and revision guards. An injected platform driver owns protocol, fixed provider endpoints, response decoding and target validation. It uses the existing bounded transport and OAuth1 signer. Application code imports neither Worker nor provider packages. Add a small usecase-local driver contract, not a generic HTTP or DI framework.

The resolved driver is an immutable snapshot for one operation, carrying platform, protocol, canonicalCallbackUrl and startConfigBinding. A resolver derives that snapshot only from copied instance configuration and supports asynchronous resolution for WebCrypto HMAC. Request Host and forwarding headers never supply callback origin. Its configuration fingerprint is a domain-separated HMAC over platform, protocol, canonical callback, fixed endpoint identity and current app credential group. Include app secrets in the signed material, never in stored/public bytes. Exclude the active user credential, target and API key; direct replacement already fences activation through revision.

## Driver operations and encrypted candidate

Driver operations are narrow: begin(state), exchange(validated callback, original request secret), confirm(candidate, explicit target), and refresh(active plaintext). Begin returns an authorization URL, optional request token and optional secret bytes. Exchange returns copied native credential plaintext bytes, nullable expiresAt, validated nullable SafeTarget and fixed missingFields. Confirm is synchronous and has no network access; it produces native active-slot plaintext after platform-specific explicit target validation. Refresh preserves native target fields and returns the new token payload/expiry; only supported protocols expose it.

Candidate missingFields uses the closed literal set `author`, `api_version`, `blog`, identifying explicit complete target fields. A character-pattern check is insufficient for diagnostic metadata. Missing app configuration fails driver resolution/start and never becomes an arbitrary candidate field name. Callback input includes an explicit decoded denial flag; it is distinct from an exchange failure and invokes no exchange.

Use one versioned, bounded candidate codec owned by the portable scope to retain credential plaintext and expiry inside the oauth_candidate ciphertext. The store's candidate columns intentionally have no separate expiry column. A simple UTF-8 JSON envelope containing version, encoded plaintext and nullable canonical expiresAt is sufficient. Decode strictly, reject unsupported versions/invalid dates/oversize data, copy byte arrays before awaits, and keep the total encrypted plaintext within the cipher's 64KiB bound. candidateTarget is safe metadata; it never authorizes silently importing a previous active target. Activation unwraps the candidate and re-encrypts native plaintext under active_slot/platform with the next generation.

## Connect, callback and reads

Connect validates platform/revision and reads the slot before external work. Explicit expectedRevision must equal that read; legacy omission uses the observed revision. Resolve keys/config and cipher before begin for both protocols, so a new operation has usable encryption configuration. Generate distinct unpredictable state and operationId, snapshot creation time, set expiry exactly 30 minutes later. OAuth1 begin performs one request; OAuth2 begin performs none. Encrypt the returned request secret with operationId and generation/schema 1, then create the operation once. A write failure never returns a usable success receipt or retries request-token acquisition. Re-read the clock after network work; do not save an already expired operation.

Callback input is bounded, decoded and platform-specific before claiming. Reject duplicate state/token/code/verifier parameters in HTTP wiring. Resolve state to the operation, compare immutable identity/configuration, then call claimOAuthCallback once. Only the claimed winner may decrypt request secret and exchange. Unknown/throwing/conflicting claim yields zero provider calls. OAuth1 uses the exact original request token and secret. Provider denial becomes a fixed failure after guarded claim, with zero exchange calls; never echo provider error descriptions. A failed exchange never restores pending_callback.

Save a candidate only after successful decode/encryption, using a fresh completion time so store expiry guards reject late responses. No callback writes active credentials. Persist fixed failure codes on claimed exchange/decryption/response failures when possible; a storage failure remains a controlled error, never success. No provider or application-level automatic exchange retry. OAuth response bodies are never archived or logged.

Operation reads require platform+operationId and an authenticated runtime route. Read-only expiry projection and current active status use existing projections/preparation. Check operation platform before exposing it. No token exchange, cipher/config requirement merely to replay a completed receipt, no TTL renewal, no writes from polling. Safe missing-field names and error codes are closed allowlists.

## Complete and refresh

Implement these as two bounded scopes: T6c2a candidate activation, then T6c2b refresh. Complete consumes the existing OAuthDriver. Refresh uses a narrow platform snapshot containing a synchronous network-free `canRefresh(plaintext)` and one async `refresh(input)` method, reusing OAuthRefreshInput/Result. Its resolver must not require SYNDROO_PUBLIC_URL or generate a callback/config fingerprint merely to refresh an existing grant. Only the existing LinkedIn OAuth2 refresh capability is in scope; a new Threads/Bluesky refresh feature is not implied by the generic API route. The preflight validates the complete native payload and presence of a usable refresh token before acquiring a lease. Concrete confirmation and refresh methods capture copied app configuration; arbitrary injected method behavior is not treated as proof of a production driver's purity.

Complete first reads the operation and validates platform. Completed operations return their original receipt with replayed=true before current key/config/revision checks; they cannot reactivate a connection. Otherwise require a valid unexpired candidate, caller revision equal to original expectedRevision and current slot revision, and unchanged configuration. LinkedIn requires explicit valid author and api_version; Tumblr requires explicit blog or validated provider candidate blog; X rejects target overrides. Never inherit old active targets or use ordinary preparation defaults to satisfy this confirmation.

Generate new bindingId and safe next payload generation before encryption. Project the receipt from this proposed committed snapshot, then call activateCandidate once with the same configuration/revision and a fresh time. Store replay wins if another complete committed first. A conflict leaves candidate and slot unchanged. A lost acknowledgement can be resolved by an explicit same-operation replay, never an automatic token exchange.

Refresh validates supported capability, active payload and presence of a refresh token before network. Acquire one 60-second lease using the observed revision; only the acquired exact snapshot authorizes one exchange. A loser/unknown lease calls no provider. Preserve bindingId, target and old refresh_token only when the response omits that field; explicit empty/wrong-type token is invalid. expires_in=0 means immediate expiry; absent expiry means null, not old expiry. Reject negative/nonfinite/wrong-type/overflow expiry. Commit with exact lease/revision and safe next payload generation. Any failed/unknown/malformed external result marks reconnect_required with the same lease/revision; never free an uncertain token for reuse. Set/remove/complete defeat late refresh results. No automatic refresh from status, publishing or Cron.

## Required bounded evidence

Each portable scope runs application typecheck/build/full tests with fake ports plus focused concurrency/lost-ack/expiry/input-snapshot/secret-sentinel regressions. Assert outbound request counts, complete slot snapshots and unchanged state on conflicts. Concrete driver tests use native outbound interception, strict response fixtures and existing transport limits; no live accounts. Real D1 and final runtime/API tests remain separate gates. Existing exhausted adapter defects are still blocked by their attempt budgets; using adapters does not establish their acceptance.

## Concrete driver composition

The next concrete scope owns new Worker composition modules and dedicated native tests. It consumes the existing provider endpoint metadata, credential decoders, boundedRequest and oauth1AuthorizationHeader. It does not copy the old Worker auth handler, add provider-package behavior, repair exhausted adapters, or create another credential-resolution framework. The legacy handler remains disconnected from the new driver until the later runtime cutover.

Copy only the required string configuration before any await. X uses X_API_KEY/X_API_SECRET, Tumblr uses TUMBLR_CONSUMER_KEY/TUMBLR_CONSUMER_SECRET, and LinkedIn OAuth uses LINKEDIN_CLIENT_ID/LINKEDIN_CLIENT_SECRET. User credentials and targets are not part of these app groups. Only connect/callback/complete resolution needs the public origin and initial configuration fingerprint; refresh resolution must still work without SYNDROO_PUBLIC_URL. A factory must not touch storage, Env binding methods, credentials outside its input, or the network during construction.

Parse SYNDROO_PUBLIC_URL as an HTTPS origin: no userinfo, non-root path, query or fragment. Generate the exact known callback path from that origin; reject control characters and unsupported schemes instead of silently stripping them. Tests use synthetic HTTPS origins and intercepted native outbound requests, not a production localhost exception. Preserve the existing confidential-client LinkedIn flow; PKCE is not introduced here.

Use the existing binding signer over a domain-separated, versioned canonical tuple containing platform, protocol, callback URL, all fixed protocol endpoints, OAuth2 scopes and the complete app group. The configuration fingerprint must change when any of those changes and remain unchanged when API key, user credential or target changes. Only the digest leaves the resolver. The same tuple and key rules apply at start, callback and completion. This use does not replace T4's remaining key and input-snapshot verification.

OAuth1 begin signs and sends exactly one request-token POST. oauth_callback includes the generated state in its query, and the exact value is both signed and sent. Require exactly one nonempty oauth_token, oauth_token_secret and oauth_callback_confirmed=true from the bounded response. Exchange signs one access-token POST using the original token and decrypted original secret plus exact verifier. Reject malformed or duplicate required form fields; do not trim opaque token values. Keep only native token fields in encrypted credential payloads. Unknown provider fields never enter errors, status or logs.

LinkedIn begin builds the authorization URL without a request. Code exchange and refresh each send one form-encoded token POST through boundedRequest, using fixed endpoints and copied app credentials. Token bodies must be strict objects with a nonempty string access_token. An absent refresh_token may preserve the old one only during refresh; an explicitly empty, null or non-string field fails. An absent expires_in gives null expiry; zero gives immediate expiry; negative, nonfinite, wrong-type or out-of-range values fail. Use a defined canonical exchange-time baseline and test exact zero/overflow behavior. The complete candidate envelope remains subject to the existing 64KiB cipher limit.

Confirmation and refresh preflight reuse the installed native payload decoders. X rejects target overrides. LinkedIn confirmation requires explicit author and apiVersion with no Env/default inheritance, and stores both native author and api_version. Tumblr confirmation uses an explicitly selected valid blog; a candidate blog can count as provider-confirmed only when it came from a defined, validated provider response. No new identity-discovery request is implied. Refresh keeps native author/api_version and safe target provenance unchanged; it does not acquire a new connection identity.

Every concrete request uses the existing 15-second/64KiB transport boundary, one underlying fetch, fixed provider endpoints and manual redirects. Map failures to fixed OAuthDriverError reasons without attaching raw causes. OAuth response bodies, headers, code, state, verifier, authorization URLs and native payloads never go to console or archives. Native tests must observe actual request URL/method/header/body, signature correctness, request counts, strict decoding, mutation-resistant configuration snapshots, zero-network confirm/preflight and secret-sentinel absence.
