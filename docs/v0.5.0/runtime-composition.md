# Worker composition boundary

Root architecture decision; runtime implementation and verification remain pending. Revision2 supersedes the legacy Worker-local business logic and fifteen-minute scheduler. Keep the existing API shape while composing the accepted application use cases.

## Construction and error mapping

Construct one request/batch-local semantic D1Repository, the narrow Queue producer, and lazy cipher/binding factories. Do not eagerly validate keys, public URL or provider credentials in the API router or dependency constructor: status, removal and idempotent/completed replay must remain possible. Read preparation uses the read cipher factory. New credential writes validate both cipher and binding key configuration. Publishing checks those configurations at its first signing call, after idempotent replay. The same preparation closure serves status, admission and execution.

The next composition slice may implement these factories independently of route cutover. Copy the allowlisted plain string configuration once; do not retain a mutable Env/config object in closures. The read cipher validates only credential key/keyId when called. The write cipher validates credential key/keyId and binding key when called. The publishing signer checks both configurations on its first sign call, then delegates to the existing HMAC signer. Cache successful immutable adapter construction within this composition only; construction itself performs no database, queue or provider operation. Instance readiness explicitly inspects all three key settings and reports only fixed missing/invalid setting names. Missing public URL affects connect, not direct publishing readiness. Keep ordinary clock reads fresh and generate opaque IDs/state/claim/lease tokens independently with runtime CSPRNG facilities.

Factory tests must distinguish construction, status, remove, stored replay, and new write/sign paths using observable call counts. Missing keys must not block construction/remove/replay, a selected unreadable D1 slot must not fall back to Env, and new encryption/publishing must fail closed before side effects. Tests against current concrete cipher/signing adapters verify composition order only; they do not resolve the separately exhausted T4 boundary evidence.

Use the native application clock/identity hooks with canonical instants and unpredictable UUID-based opaque identifiers. Pass only a copied string configuration map to strategies and OAuth drivers. No application module receives Env, Queue message handles or Request headers.

Map documented application errors to fixed HTTP error bodies. Preserve INVALID_REQUEST=400, IDEMPOTENCY_CONFLICT=409, existing platform-not-configured=422, AUTH_CONFLICT/AUTH_IN_PROGRESS=409, NOT_FOUND=404, PROVIDER_ERROR=502, INSTANCE_NOT_READY/STORE_UNAVAILABLE=503. Unexpected errors become fixed INTERNAL_ERROR=500. Error logging records fixed event/method/route category/code only; never raw error.message, request path/query, provider body or auth input. Auth/diagnostics/callback failures retain the same no-store security headers as successes.

## HTTP routes

Retain public health and exact post read/create paths. Parse post structure without consulting credentials; new admission uses application preparation, and replay must precede current credential/key checks. Preserve maintenance behavior and 202 new acceptance / 200 replay. Avoid a second post business implementation in Worker wrappers.

Authenticate every v1 path except exact GET `/v1/auth/{x|tumblr|linkedin}/callback`. Prefix matches, extra suffixes, unsupported callback platforms and other methods do not bypass Bearer. Decode bounded auth object bodies and reject unknown fields. Empty legacy delete/refresh bodies mean observed-revision compatibility, never an unguarded mutation. Separate expectedRevision from direct credential fields. Strictly decode callback query cardinality and protocol fields; never use Host/forwarding headers to choose callback origin. Return fixed local callback HTML without provider strings, remote resources or secrets, with no-store, no-referrer and restrictive CSP.

Legacy repository public list/get projection still needs convergence with the semantic repository. The current semantic class exposes no listPosts/getPost methods; the legacy class still performs obsolete mutations. Do not silently retain two concrete mutation repositories, expose storage rows directly, or treat missing public projection as an accepted D1 result. Coordinate any repository source addition with the exhausted T3 scope and its revised attempt authorization.

The inbound JSON reader is a separate HTTP boundary from the outbound transport. Preserve its 64KiB byte cap and content-type checks, copy received chunks, and add a total fifteen-second read deadline plus request cancellation. A pending read or a hanging cancellation promise must not delay the response indefinitely. Dispose the reader without awaiting cancellation forever; handle late rejections and release its lock. Reject malformed UTF-8/JSON with fixed messages, never decoder text or submitted bytes. Body timeout/cancellation uses controlled INVALID_REQUEST; size and media-type failures retain the existing 413/415 contract. An optional empty legacy mutation body must be distinguished from malformed nonempty JSON, and no mutation starts until decoding finishes. Native tests must exercise held-open, oversized and buffer-reuse streams, including no-store headers on failures.

## Main queue and DLQ

Route by the configured exact physical queue name, while retaining PUBLICATION_QUEUE as the producer binding. Queue names belong to runtime configuration, not application. Unknown queue names cause a fixed operational error and zero provider calls. Configure finite retries for both consumers and prevent a DLQ from forwarding to itself.

For main messages, pass unknown body to executePublication; map settled to ack and infrastructure_retry to bounded broker retry. Unexpected adapter failures also become infrastructure retry without raw text. Never interpret the old publicationId-only protocol as v1. Business retries already commit a future outbox job and settle the old message; runtime does not turn them into delayed broker retries.

For DLQ messages, call settleDeadLetterMessage only. Valid messages ack after authoritative metadata settlement; store failure retries. Malformed messages emit a fixed quarantine event before ack, with no payload-derived IDs/platform and no domain writes. Logger failure must not be reported as successful alert delivery. Local tests prove alert emission/ack ordering, not production log-export durability. Deployment observability configuration remains a separate verification limit. The frozen SanitizedArchive requires a known platform; do not invent one for malformed input merely to force it into that format.

Valid DLQ diagnostics may use a separate bounded best-effort category/key with ninety-day retention. They must not call recordArchiveResult for a publication's provider attempt, overwrite its archive status, trigger a new provider call, or undo settled metadata when R2 fails. No raw body is archived. Provider archive retention remains thirty days.

The queue mapping can be implemented and tested in a separate composition/queue-consumer module before the coordinated index/routes cutover. Accept a native MessageBatch<unknown>, copied distinct physical queue names and the existing ExecutePublicationDependencies/SettleDeadLetterDependencies. Import the accepted application functions directly; do not recreate envelope decoding or business retry policy. Keep the current legacy entrypoint untouched until the complete runtime cutover can replace it consistently. Acceptance of this module is not acceptance of the still-legacy exported Worker entrypoint.

Process messages sequentially. Main settled outcomes acknowledge; infrastructure outcomes and unexpected use-case exceptions request a fixed sixty-second broker retry. DLQ settled outcomes acknowledge after metadata completion. Quarantine requires successful completion of the fixed alert write before acknowledgement; accept synchronous or Promise-returning sinks and await the result. If it throws or rejects, request a broker retry and do not acknowledge. A TypeScript void-return callback also accepts async functions, so ignoring the return would permit acknowledgement before a failed alert. Do not treat a swallowed optional application log as proof that the required quarantine alert succeeded. Unknown/missing/equal queue-name configuration throws a fixed operational error before any domain call or acknowledgement. Validate the batch queue before reading its messages; malformed message collections also receive a fixed error. Queue names and exception strings must not appear in that error. Test message ack/retry call counts and ordering, including native queue results, duplicate/future messages, main malformed input, DLQ malformed input, store failure, pending asynchronous alerts and failed logging. Deployment retry-count limits and DLQ resource topology remain source-configuration work in T9.

## Scheduled work and diagnostics

Run bounded maintenance and dispatcher each minute. Portable orchestration calls existing semantic recovery/cleanup ports; it performs no provider or refresh request. Dispatch caps at twenty jobs, subject to measured D1 statement/row budgets; a guessed batch size is not budget evidence. Fixed numeric reports describe completed calls, not assumed success. A failed phase cannot invent a zero count or a successful maintenance report.

Expose read-only authenticated diagnostics through DiagnosticsReader. Unknown storage measurements retain null, fixed reason and observedAt; no management token or extra remote request is introduced. Do not use diagnostic reads to repair, unlock or clean state.

The portable maintenance slice can compose existing PublishingStore.recoverStaleClaims, CredentialStore.cleanupExpired, OutboxStore.collectFinished and dispatchReadyJobs. These are separate transactions, so report each phase's outcome independently; do not claim atomicity across the whole wake. Capture a fresh canonical clock at each phase. A failed cleanup phase must remain visibly failed rather than returning zero removed. A fixed total deadline stops starting later phases and new sends; it cannot cancel a D1 mutation or broker send already accepted. Clock and continuation checks must not introduce provider calls. Keep per-phase row limits explicit and dispatch at most twenty; final profile sizing still depends on T3's actual statement/row measurements.

Maintenance is not a refresh recovery actor. It may project an expired uncertain refresh as requiring reconnect, but it cannot reuse the token, clear its safety fence or silently change the active connection. OAuth cleanup retains completed receipts while clearing expired secret material. Outbox collection keeps all active, unresolved and unknown-associated records according to its existing semantic port. A source review and fake-port test cannot replace the pending real-D1 query-plan and race evidence.

The independent scheduled-runner slice may add a composition/scheduled-maintenance module around the accepted runMaintenance function before entrypoint cutover. Require explicit MaintenanceLimits from the eventual measured profile; no guessed production row limits. Give each wake a twenty-second total runtime deadline, with internal test options allowed to lower it. Capture dependencies and limits before starting. Use a latched continuation check passed to the application, and race completion against the deadline so a held-open binding cannot hold the runtime wrapper indefinitely. On deadline, latch stopped before returning a fixed timeout outcome with no invented phase counts. A pending operation may finish afterward; observe its eventual rejection, prevent every later phase/send, and never claim the already accepted operation was cancelled. Clear timers on every completed/error path. Completed reports retain application phase failures exactly. Unexpected failures use a fixed error without raw detail. Native tests must cover held-open recovery, a send completing after the deadline, no later work, normal/error timer cleanup, concurrent wakes with independent stop state, and an explicit limit above twenty still capped by the accepted dispatcher. This slice does not change scheduler.ts/index.ts, choose a D1 query budget, implement diagnostics, or accept the production Cron profile.

## Required evidence

Native workerd fixtures must exercise HTTP auth boundaries, replay with absent keys, encrypted set/remove/complete, versioned queue ack/retry and DLQ routing, provider call counts, bounded scheduler behavior and secret-sentinel scans. Fake ports can isolate runtime mapping, but cannot replace real D1 concurrency or R2/cipher gates. Existing transport, D1 and storage scopes remain unaccepted until their remaining corrections and evidence are explicitly authorized and verified.
