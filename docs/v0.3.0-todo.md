# v0.3.0 architecture TODO

Goal: improve data-model clarity, publishing orchestration, and testability through
small interfaces that hide meaningful complexity. Do not rewrite the application
or add layers merely to reorganize files.

This is a planning checklist, not authorization to implement, change public
contracts, publish, deploy, or commit and push. Reliability defects remain
[v0.2.0 release gates](v0.2.0-todo.md), not deferred refactoring work.

Sections 1 to 6 are implemented in the source tree. See the
[v0.3.0 implementation record](v0.3.0-implementation.md) for the selected scope,
the data-model classification, the executed gate results, the disposable
template rehearsal, and the deferred items. This remains a validated candidate
baseline rather than an accepted release: `@syndroo/cloudflare-worker` is still
`0.2.0-rc.1`, unpublished, untagged, and undeployed, and live-account validation
is outstanding.

## Future triggers, not automatic v0.3.0 scope

- **Multiple accounts or OAuth:** design publishing targets, account ownership,
  credential lifecycle, and idempotency scope before implementation. The current
  one-publication-per-Post-and-platform constraint cannot represent multiple target
  accounts on the same platform without a deliberate model change.
- **Manual reconciliation UI:** decide what attempt history, verification evidence,
  and operator actions must be retained. The latest error is not an audit trail;
  no UI, retry endpoint, or event-sourcing framework is implied by this plan.
- **Second database:** design a storage seam around real required behavior, not
  generic CRUD. Preserve concurrency guarantees across implementations.
- **Second runtime:** consider runtime abstraction only when a concrete supported
  deployment target requires it; keep Cloudflare code outside core.
- Media, tenancy, additional platforms, and managed hosting remain separately
  scoped product work, not prerequisites for these internal improvements.
